feat: guard torch._numpy.random.shuffle row-multiset corruption (pytorch/pytorch#197795)

torch._numpy.random.shuffle on a torch.Tensor, under
use_numpy_random_stream=True, does not perform a true in-place
permutation of the tensor's rows -- it can duplicate some rows and
silently drop others. Reproduced from scratch on this host (torch
2.14.0, CPU): sorted(rows_after) != sorted(rows_before) after a
seeded stream-mode shuffle.

safe_row_shuffle/safe_row_shuffle_ replace the unsafe path with
torch.randperm + index_select, a pure gather over a bijective index
permutation that provably preserves the row multiset by construction.

44/44 tests pass locally (100% coverage), including a regression test
that reproduces the real unguarded bug via torch._numpy.random.shuffle
directly (would fail if upstream silently fixes it, per the test's own
docstring) and a diagnose() end-to-end check that the guard is fully
effective across multiple seeds/shapes.
